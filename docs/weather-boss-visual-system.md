> 状态：`asset-kit-generated-visual-qa-passed-pending-integration`
> 范围：定义视觉方向、token、布局母语和首批母资产，冻结可复现的 SVG/PNG 生产与清单校验，并完成三套目标视口联系表与位图 1×/2× 透明边缘检查；本稿不接入业务、不修改现有 CSS 或组件。

## 1. 主题、受众与页面唯一任务

- **具体主题**：全国气象证据在一台持续运转、带盐蚀与归档痕迹的夜间雷达终端中被登记、核验并升格为风险事件。
- **主要受众**：在直播画面前远距离观看的普通观众；操作员是次要受众，交互控制不得压过直播可读性。
- **页面唯一任务**：让观众在 3 秒内识别“当前全国最高可信风险是什么、发生在哪里、证据是否仍新鲜”。
- **世界观边界**：这是气象证据终端，不是通用电竞面板、赛博朋克驾驶舱或末世武器界面。磨损来自盐雾、潮气、刮擦、热敏纸压痕和长期值守，不使用血迹、弹孔、骷髅或武器化符号。

## 3. 冻结色彩 token

首批视觉资产只允许直接使用以下 6 个不透明基色；阴影、描边和背景层通过 alpha 变化取得，不再新增竞争性色相。

| Token | Hex | 角色 | 使用约束 |
| --- | --- | --- | --- |
| `terminal-void` | `#05080A` | 夜间终端底色 | 大面积背景；不作为“无数据”的唯一提示 |
| `archive-ivory` | `#ECFBFF` | 主要文字与档案亮面 | 正文、关键地名和数值；避免纯白刺眼面积 |
| `telemetry-cyan` | `#00D8FF` | 测量、图层、来源在线/蓝色预警基色 | 非危险结构线保持低 alpha；不得用作红橙警报光晕 |
| `official-red` | `#FF3B32` | 官方红色预警与同等级风险 | 最高视觉权重专用；普通装饰禁用实心红块 |
| `official-orange` | `#FF8A2A` | 官方橙色预警 | 只用于封条、等级边和对应事件徽记状态 |
| `signal-amber` | `#FFB000` | 官方黄色预警、观察态刻度和键盘焦点 | `watch` 必须再配虚线/眼形缺口，不能只靠颜色 |

语义映射：蓝色预警使用 `telemetry-cyan` 的实线双边框；`watch` 使用 `signal-amber` 的虚线边框与缺口形态；失效/不可用状态使用 `archive-ivory` 低 alpha 加斜线，不新增灰色危险等级。红、橙、黄、蓝、观察态在形状和纹理上也必须不同，保证色盲可辨识。

## 4. 字体角色（只用现有本机栈）

不引入外网字体，不在资产中烘焙文字。

- **Display / 关键标题与城市名**：`"Bahnschrift SemiCondensed", "Bahnschrift", "Microsoft YaHei UI", sans-serif`。用于品牌、事件名、城市名、预警等级；建议 700–900，直播主标题不小于 28px。
- **Body / 中文解释与限制**：`"Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`。用于事实句、行动提示、限制与错误；建议 600–700，直播正文不小于 16px。
- **Utility / 时次、来源、坐标与短标签**：`"Bahnschrift", "Consolas", "Microsoft YaHei UI", monospace`。使用 tabular numbers；直播关键时次不小于 16px，辅助标签不小于 12px。

若 Bahnschrift 不可用，回退后必须以目标直播截图重新检查中文/拉丁混排宽度，不允许靠缩小字号解决溢出。

## 5. 布局概念：证据跑道（Evidence Runway）

全国总览和台风指挥共用同一骨架：地图是连续主场，最高风险位于左上阅读起点，来源健康贴近其证据链；图层与时间轴退到右侧/底部。所有卡片沿一条“证据升格轨”登记，而不是散落成等权小卡。

```text
┌──────────────────────────── 直播顶栏：品牌 / 当前镜头 / 同步时次 ────────────────────────────┐
│ ┌ 最高可信风险 ─────┐ ║证据升格轨║                                      ┌ 图层 / 来源健康 ┐ │
│ │ 地点 + 等级       │ ║ source→time→seal ║        全国地图主场            │ ○ □ △ / 时效    │ │
│ │ 事实 + 限制       │ ║              ║                                │ 播放 / 暂停      │ │
│ └───────────────────┘ ║              ║                                └─────────────────┘ │
│                         ║              ║                                                   │
│                         ║              ║                                                   │
│ ┌ 主事件档案碎片 ──────┴──────────────┴──┐   ┌ 城市/台风次级档案（按需） ┐                │
│ └─────────────────────────────────────────┘   └──────────────────────────┘                │
└──────────────────── 雷达时间轴 / 数据时次 / 播放状态 ─────────────────────────────────────┘
```

窄屏不把地图切成更多小格，而是将最高风险档案固定在上方，地图保持中段连续，来源健康和时间轴合并为底部抽屉。红橙封条只允许出现在最高风险档案和对应事件入口，不能铺满导航或普通按钮。

## 6. 唯一 signature：证据升格轨

“证据升格轨”是一条带气象刻度与归档缺口的连续细轨，从来源节点经过数据时次，最终进入事件封条。它同时表达：

1. 这条结论从哪里来；
2. 数据是否最新、延迟、过期或不可用；
3. 何时从观察信号升格为官方风险。

母资产只提供无文字的轨道、节点与封条插槽，状态标签由 HTML 渲染。它是唯一允许跨多个区块连续出现的装饰性结构；其余边框、磨损和扫描线保持克制，避免多个“招牌效果”争抢注意力。

## 7. 自我审查与一次修正

**初稿泛化风险**：沿用现有图集继续增加红/青霓虹边框、圆形准星、酸绿色状态灯和高细节机械破损，会得到任何科幻控制台都能使用的通用 HUD；同时红光、血迹式斑点和警戒条会抢占官方红橙预警的权重。

**已修正**：

- 删除酸绿色新 token，来源健康改为形状 + 文本 + 冷青/低 alpha 米白；
- 删除无功能的圆形能量环，圆形只保留给真实雷达/时间轴控件；
- 机械损伤改为盐蚀、刮擦、氧化边与档案压痕，不使用血迹、弹孔或武器符号；
- 全框霓虹改为哑光暗面 + 局部测量线，只让真实红橙风险形成高亮；
- 将记忆点集中到“证据升格轨”，使视觉身份来自气象证据流程，而不是赛博朋克装饰密度。

## 8. Weather Boss HUD Kit 组合规则

资产登记见 `public/assets/weather-boss/manifest.json`。为避免近似文件枚举，首批采用“母版 + 语义输出”结构：

- HUD 框、角标、分隔、纹理由一套中性结构母版组成；颜色由 CSS token 注入。
- 六类事件徽记共享同一外轮廓、安全区和线宽，只替换内部气象象形。
- 红/橙/黄/蓝/`watch` 封条共享 `risk-seal-master.svg` 几何母版；语义输出只改变颜色、边型和纹理。
- 来源健康使用一张 SVG symbol 集，在线、延迟、过期、不可用、无记录必须有不同轮廓。
- 全国与城市档案件只提供边缘、夹层、底纹和警戒装饰；正文、数字、排名、地名、预警标题始终由 HTML 渲染。

位图只用于可平铺纹理、磨损 alpha、光效和氛围；图标、状态、封条和可缩放结构优先 SVG/CSS。任何位图母资产需按 2× 目标检查后再降采样。

## 9. 后续资产生成提示约束

主控确认 manifest 后，每个生成提示必须同时包含以下约束：

1. 明确资产种类、文件名和使用场景，不生成整页 UI 截图替代母资产；
2. 材质为夜间海岸气象终端的哑光金属、盐蚀、细刮擦、热敏档案压痕；照明以冷青测量光为辅；
3. 严格使用冻结 token；红橙只服务官方高等级风险；
4. 透明背景、无文字、无数字、无地名、无排名、无品牌、无 logo、无水印；
5. 指定目标像素尺寸、透明边缘、9-slice / 可裁切 / 可平铺要求；
6. 小尺寸轮廓清晰，减少微小线路、伪文字和无功能装饰；
7. 不含血迹、弹孔、武器、骷髅、灾难照片或可误读为真实气象符号的图案；
8. 对红/橙/黄/蓝/`watch` 输出保持同一几何母版，不得逐张自由改造；
9. 记录生成模型、版本、日期、完整提示、后处理和许可条款，未记录不得从 `planned` 升为 `approved`。

每批审核：透明边缘无黑/白脏边；1× 与 2× 缩放清晰；纹理接缝不可见；压缩无影响辨识的色带；红橙层级高于观察态；1920×1080、1366×768 和当前直播画布截图均通过；`prefers-reduced-motion` 下不依赖扫光理解状态。

## 11. 位图生产与来源冻结

四个位图均为无文字 RGBA 资产。扫描线与全国地图暗角由 `scripts/generate_weather_boss_png_assets.mjs` 的共享 RGBA 原语确定性生成；终端盐蚀与档案压力颗粒由内置 imagegen 生成纯色 chroma-key 源，再通过统一的去色键、缩放、灰度化与 PNG 编码管线导入。完整 prompt、调用 ID、源文件名、源 SHA256、后处理、许可说明和最终 SHA256 均登记在 manifest，不依赖 README 式口头说明。

```powershell
node scripts/generate_weather_boss_png_assets.mjs
node scripts/generate_weather_boss_png_assets.mjs --source=terminal-abrasion=<absolute-source-path> --source=archive-paper-grain=<absolute-source-path>
node scripts/generate_weather_boss_png_assets.mjs --check
node scripts/generate_weather_boss_svg_assets.mjs --check
```

不带 `--source` 时只重建确定性资产，不会伪造或替换 imagegen 来源；带来源导入时，脚本先验证文件名与源 SHA256，再执行冻结的后处理。`--check` 对尺寸、RGBA、透明像素、可见像素、最终 SHA256、生成器、来源和许可做硬校验；文件存在但仍标记为 `planned` 会直接失败。

视觉 QA 由 `scripts/generate_weather_boss_visual_qa.mjs` 生成，证据位于 `evidence/screenshots/weather-boss-assets-*.png`、`weather-boss-bitmap-alpha-2x-qa.png` 与 `weather-boss-assets-visual-qa.json`。联系表只组合 manifest 中登记的资产，不另造“示意资产”。
