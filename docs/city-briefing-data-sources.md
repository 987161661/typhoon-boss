# 城市精细战况卡：数据来源与证据边界

`GET /api/city-briefing?city=杭州` 是直播城市卡的事实层。它不调用大模型，也不输出未经校准的灾害概率。MiniMax 如用于播报，只能根据该接口的字段改写，且必须保留 `sources`、`warnings` 和每项 `evidenceLevel`。

## 已可直接使用：Open-Meteo

- 城市名解析与经纬度：Open-Meteo Geocoding。
- 城市当前条件：气温、体感温度、湿度、降水、风和阵风。
- 未来 6 小时：逐小时降水、降水概率、阵风、CAPE、气压和水汽。
- 证据级别固定为 `model`：它是坐标点的数值天气产品/分析场，不可称作本地站实测，也不可说成官方预警。

## 配置后启用：和风天气（QWeather）

配置控制台-设置给出的 `QWEATHER_API_HOST`。普通天气数据可使用
`QWEATHER_API_KEY`，官方预警使用服务端 Ed25519 JWT（项目 ID、凭据 ID 和私钥）后，接口会请求：

- `/v7/minutely/5m`：中国境内未来 2 小时、1 km、每 5 分钟降水预报；适合“雨带何时增强/何时减弱”的城市卡。
- `/weatheralert/v1/current/{latitude}/{longitude}`：官方预警转发；有预警时它优先于项目自己的风险规则。旧的 `/v7/warning/now` 已弃用，不能再作为预警链路。

API Key、JWT 和私钥只可留在服务端环境变量或本地被忽略的 `.secrets` 中，不能暴露给浏览器。请按和风天气的授权范围和署名要求使用；成功查询到空预警列表仅代表当前未检出官方预警，不等于无风险。

## 仍不能声称的结论

- 龙卷风发生概率：需要经过历史回测与校准的概率模型，或官方概率产品；CAPE、降水和卫星图不足以给百分比。
- 大陆任意城市的分钟级雷达外推：目前没有接入覆盖中国大陆的可授权雷达格点产品。
- 城市内涝已经发生：需要本地雨量站、积涝点、排水/水位或官方事件源。

## 面向 MiniMax 的输出约束

1. 官方预警用 `confirmed`；模型字段用 `model`；不可混用。
2. 不得将 `maxPrecipitationProbabilityPct` 改写为“暴雨发生概率”或“灾害概率”。它只表示指定模式集合对逐小时降水的概率。
3. 不得在 `warnings` 非空、字段为 `null` 或来源 `unavailable` 时补写数值。
4. 每次输出仅保留一个主风险、两个次风险和最多三条行动建议。
